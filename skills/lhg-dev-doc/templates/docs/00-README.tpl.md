# 文档体系导航（{{PROJECT_NAME}}）

> 本文档是 docs/ 的**总入口**：一眼看全目录结构、按需知道读哪份/写哪份。
> 详细规则见仓库根目录 `project_rules.md`（薄宪法），本表只做导航速查。

## 一、目录结构（编号-英文，中文说明）

| 编号 | 目录/文件 | 用途 | 生命周期 |
|---|---|---|---|
| 00 | `00-README.md` | 本文件：文档体系导航 | 长期维护 |
| 10 | `10-glossary.md` | 术语表（项目特有缩写/状态码/易混命名） | 长期维护 |
| 11 | `11-directory-map.md` | 代码目录 ↔ 模块文档 三列地图（任务入口索引） | 长期维护 |
| 30 | `30-requirements/` | 原始需求＆外部文档**索引**（锁"哪份最新"；二进制原件原位） | 只读留档 |
| 40 | `40-analysis/` | 分析产物（功能拆解/模块分析/接口反推） | 临时，用后 merge 或删 |
| 50 | `50-summaries/` | 结项总结（对接/迭代完成后的一文读懂） | 结项定格 |
| 60 | `60-flows/` | 端到端业务流程（跨模块时序，篇幅大） | 长期维护 |
| 70 | `70-modules/` | 模块镜像文档（职责/契约/状态机/坑） | 随代码更新 |
| 80 | `80-changes/` | 进行中的变更方案（一人一文件） | 完成即归档 |
| 90 | `90-archive/` | 已完成变更归档 | 冷库，不主动加载 |
| 99 | `99-personal/` | 个人草稿（按人分目录） | 默认不参与分析 |

## 二、我该读哪份（按任务类型）

| 任务 | 读 |
|---|---|
| 改某模块代码 | `11-directory-map.md` → 命中行 → 对应 `70-modules/<模块>.md` |
| 查术语/状态码含义 | `10-glossary.md` |
| 确认需求/哪份接口文档最新 | `30-requirements/README.md` |
| 排查历史"当初为什么这么改" | `90-archive/` 或对应 module 的「决策与坑」段 |
| 理解一段跨模块业务全流程 | `60-flows/<流程>.md` |

## 三、我该写哪份（按产出类型）

| 产出 | 写 |
|---|---|
| 理解需求/代码的中间分析 | `40-analysis/`（用后 merge 进 module 并删除） |
| 某模块的职责/状态机/坑 | `70-modules/<模块>.md`（≤200 行，不抄字段清单） |
| 某个对接/迭代做完的总结 | `50-summaries/<主题>总结.md` |
| 一个待实施的变更方案 | `80-changes/<yyyyMMdd>-<主题>.md` |
| 自己没定型的草稿 | `99-personal/<姓名>/`（默认不进分析） |

## 四、三类边界速查

- 原始需求（对方给的）= `30-requirements/`，只读，别搬别抄。
- 分析产物（我方过程稿）= `40-analysis/`，用完就删，别滞留。
- 持久真相（随代码变的活文档）= `70-modules/` + `60-flows/` + `10-glossary` + `11-directory-map`。
- 结项总结（定格快照）= `50-summaries/`。
