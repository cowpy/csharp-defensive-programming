# summaries 目录（结项总结 · 定格快照）

> 放「某个对接/功能/迭代完成后」提炼的**一文读懂总结**：背景 → 目标 → 方案 → 关键决策 → 踩坑 → 最终状态。

## 定位
与 `70-modules/`（随代码更新的活文档）互补：modules 按**代码模块**组织、随代码变；
summaries 按**项目/对接/迭代**组织、**结项定格**（完成后基本不改）。

## 结构建议（一文读懂）
1. 背景与目标
2. 方案概览（含架构/报文/状态机速览，不抄逐字段）
3. 关键决策与取舍（为什么这么做）
4. 踩坑与教训（带上下文，不写泛泛的"注意性能"）
5. 最终状态与遗留项

## 命名
`<业务域>-<主题>总结.md`，如 `ATS-付款接口对接总结.md`。
