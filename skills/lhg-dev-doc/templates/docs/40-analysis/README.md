# analysis 目录（分析产物 · 临时 · 用后即焚）

> 放「理解需求/代码」过程中产生的**中间分析文档**：功能点拆解、模块划分、接口反推、时序梳理、变更分析。

## 定位
分析文档是「模块文档的原料」，不是终点。它的价值是把糊涂的理解写清楚；
一旦理解固化进 `docs/70-modules/*.md` 或 `docs/80-changes/*.md`，原料就该销毁——**只增不减的分析文档必然腐化**。

## 生命周期（强制）
1. 分析任务 → 在此目录写 `<yyyyMMdd>-<主题>-analysis.md`；
2. 任务收尾时**二选一**：
   - 结论有效 → 细化后 merge 进对应 `70-modules/*.md`（或 changes 方案），**然后删除本文件**；
   - 结论无效/已被取代 → 直接删除。
3. 禁止 analysis 文档长期滞留；提测前/发版前必须清理一次。

## 命名与归属
- 文件名带日期 + 主题 + `-analysis` 后缀，避免与其他文档撞名。
- 一份分析对应一个主题/模块，不写"大杂烩"。
- 个人未定型的探索性笔记先放 `99-personal/<姓名>/`，不要混进本目录。
